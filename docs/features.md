- [o] M4 — P1: The moai surface page lists the SPEC folders of the project through the files sidecar, and replaces the moai web console of M3 (no web server is started). Input: the `list` and `watch` operations of `@soksak/sidecar-files` on `.moai/specs` (core `docs/spec/sidecars.md`). Expected: `plugin.json` declares `@soksak/sidecar-files` `^0.0.11` in `dependencies` and the surface view `ui/specs.html` with no region; `specIds` returns the SPEC folder names in name order and rejects a failed reply with its text; the page lists again on each `changed` event, and watches the first path of the chain `.moai/specs`, `.moai`, project root that the sidecar accepts. Timers and fallbacks of moai web, with the event source that replaces each: (1) the client poll every 30 s (`assets/app.js` `POLL_MS`), used when the browser has no EventSource or after three SSE errors, replaced by the files sidecar `changed` events; a sidecar failure answers `{error}` or `onFailure`, which the page shows and does not poll for. (2) The SSE keepalive every 25 s and the 10 s read-header timeout of the server (`events.go`, `server.go`) belong to the moai HTTP server, which this page does not run. (3) The 1 s retry ticker of the file watch (`events.go`), which re-adds missing watches, is replaced by the watch chain: a watch that fails for a missing path moves to its parent, and the `changed` event of the parent starts the chain again when the path appears. (4) The 250 ms debounce (`events.go`) coalesces a burst of changes; the page starts no timer and sends one `list` for each reply cycle, so bursts cost requests but no delay. (5) The 5 s shutdown drain (`server.go`) and the 1.2 s copy-feedback timer (`assets/app.js`) have no counterpart in this page. Missing event: none for macOS and Linux. Windows has no directory watch (`watching directories is not implemented on windows`, files sidecar `docs/spec/files.md`), so the page shows that error and does not fall back to polling; Windows work is out of scope (no Windows work without instruction). Progress: `test/surface.test.mjs`, `test/specs.test.mjs` and the manifest test fail on the old declarations, the missing watch exports and an inserted `setInterval` in `ui/specs-model.js` (Red), then all 21 tests pass (Green). - [!] M10 — P2, screen overview of M8: Held: the overview cannot show the same information. Cause: (1) the session state `live` is set when the PID of a registry entry is alive or its heartbeat is fresh (`processAlive` → `session.IsProcessAlive`, `viewmodel_ops.go`), and no core contract reports the liveness of a PID to a plugin page (`sok process wait` is a CLI command, and a page cannot run it). A heartbeat-only state would show other sessions. (2) The MUST-FIX findings and the status of each SPEC come from `a.specs.get(root)`, the Go spec parser and linter of moai, and no contract gives a plugin page the result of a moai command. Retry when: a core status reports the liveness of a process by PID to a plugin page, and a declared command returns the output of a moai command (or the owner decides that the page reads the linter rules as a copy).
