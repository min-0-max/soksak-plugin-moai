- [o] M1 — P1: manifest가 moai 메이커 group을 선언해요. `plugin.json`은 plugin `agents`를 `dependencies`에 적고, extension point `agents.makers`에 item 하나를 기여해요. item의 `module`은 M5의 group module이에요. 입력: manifest. 기대: `dependencies`는 `{ "agents": "^0.0.1" }`, `contributes`는 `{ "agents.makers": [{ "range": "^0.0.1", "module": "ui/makers/moai.js" }] }`이고, 다른 field는 없어요. 진행: `test/manifest.test.mjs`가 manifest가 없는 상태에서 실패한 뒤(Red), 5/5 통과해요(Green). Range는 임시값이에요. 아직 어떤 repository도 extension point `agents.makers`의 version이나 item schema를 선언하지 않아서, `agents` release가 선언하면 `^0.0.1`을 바꿔요. module 파일은 M5예요.
- [ ] M2 — P1: 설치 때 moai plugin 폴더를 교정해요. 입력: `moai`의 release(`--plugin-dir` 원본). 기대: 설치된 `<plugin data>/plugin/`에서 hook 등록은 `${CLAUDE_PLUGIN_ROOT}` 기준 `hooks/hooks.json`으로 옮겨지고, 계정 설정은 계정 `settings.json`으로 옮겨지며, 프로젝트에는 `.moai/`만 시드되고, `moai:moai:` 이중 이름은 없어요(club.md, 측정 M1–M4). 기다리는 것: 프로젝트 `settings.local.json`을 `.moai/` 아래에 쓰지 않는 고정된 upstream moai release예요. fork는 필요 없어요. 교정은 고정된 upstream release가 설치한 plugin 폴더에서 실행되고, plugin은 자기 파일만 바꿔요.
- [o] M3 — P1: surface가 moai web document region을 선언해요. `plugin.json`은 최상위 `mark`와 `icon`, 그리고 `surface` composition을 선언해요. composition은 page `ui/web.html`의 `view`이고, document region `moai-web`(`input` `native`) 하나를 가져요. overlay는 없어요. page는 `data-region="moai-web"` element를 가지고 script는 없어요. 진행: `test/surface.test.mjs`가 surface가 없을 때 실패한 뒤(Red), plugin의 test 10개가 모두 통과해요(Green). `test/manifest.test.mjs`의 field 목록에 `mark`, `icon`, `surface`를 같은 변경에서 더했어요. surface가 그 field를 추가하기 때문이에요. Region에는 overlay가 없고 page는 script를 불러오지 않아요. Controller는 M4가 써요.
- [o] M4 — P1: moai surface page가 files sidecar로 프로젝트의 SPEC 폴더를 목록으로 보여 주고, M3의 moai web console을 대체해요(web server는 시작하지 않아요). 입력: `@soksak/sidecar-files`의 `list`와 `watch` 작업을 `.moai/specs`에 보내요(core `docs/spec/sidecars.md`). 기대: `plugin.json`은 `dependencies`에 `@soksak/sidecar-files` `^0.0.11`을 선언하고, surface view `ui/specs.html`을 region 없이 가져요. `specIds`는 SPEC 폴더 이름을 이름순으로 돌려주고, 실패한 답은 그 text로 거부해요. Page는 `changed` 이벤트마다 목록을 다시 받고, `.moai/specs`, `.moai`, 프로젝트 root 순서의 chain에서 sidecar가 받아 주는 첫 경로를 watch해요. moai web의 timer와 fallback, 그리고 각각을 대신하는 event source: (1) 30초마다 하는 client polling(`assets/app.js`의 `POLL_MS`)은 browser에 EventSource가 없거나 SSE 오류가 세 번 난 뒤 쓰여요. files sidecar의 `changed` 이벤트가 이것을 대신해요. Sidecar 실패는 `{error}` 답이나 `onFailure`로 오고, page는 그것을 보여 주고 polling으로 내려가지 않아요. (2) 25초 SSE keepalive와 10초 read-header timeout은 moai HTTP server(`events.go`, `server.go`)의 것이고, 이 page는 그 server를 실행하지 않아요. (3) 1초마다 누락된 watch를 다시 추가하는 file watch retry ticker(`events.go`)는 watch chain이 대신해요. 없는 경로의 watch는 상위 경로로 넘어가고, 상위의 `changed` 이벤트가 그 경로가 생겼을 때 chain을 다시 시작해요. (4) 250 ms debounce(`events.go`)는 변경 burst를 묶어요. Page는 timer를 시작하지 않고, 답 하나마다 `list` 하나를 보내요. 그래서 burst는 요청을 더 쓰지만 지연은 없어요. (5) 5초 shutdown drain(`server.go`)과 1.2초 복사 피드백 timer(`assets/app.js`)는 이 page에 대응하는 것이 없어요. 누락된 event: macOS와 Linux는 없어요. Windows는 디렉터리 watch가 없어서(`watching directories is not implemented on windows`, files sidecar `docs/spec/files.md`) page가 그 오류를 보여 주고 polling으로 대신하지 않아요. Windows 작업은 지시가 있을 때만 해요. 진행: `test/surface.test.mjs`, `test/specs.test.mjs`와 manifest test가 이전 선언, 없는 watch export, `ui/specs-model.js`에 넣은 `setInterval`에서 실패한 뒤(Red), 21개 test가 모두 통과해요(Green). Page 연결은 application에서만 실행되어, 그 왕복은 M8의 window check로 확인해요.
- [o] M5 — P1: group module `ui/makers/moai.js`가 moai group을 `agents.makers`에 기여해요. 입력: 교정한 copy의 agent와 스킬을 담아 release build가 쓰는 `maker/index.json`이에요([group](group.ko.md)). 기대: `group()`은 plugin modules 경로로 index를 읽고, `makers.md`의 group 객체를 돌려줘요. moai 정체성, `clis` `claude`, `plugin` `plugin`, `variables` `MOAI_HOME={home}/.moai`, `path` `bin`, `folders` `.moai/`, 규칙 한 줄을 담고 port는 없어요. 모양이 다른 index는 index와 field를 적어 거부해요. 진행: `test/group.test.mjs`가 module이 없을 때 실패한 뒤(Red), 배포 모양의 fixture를 HTTP로 제공해서 3/3 통과해요(Green). `maker/index.json`과 `plugin/`을 쓰는 release build는 M2이며 fork를 기다려요.
